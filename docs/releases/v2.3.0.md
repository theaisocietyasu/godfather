Godfather 2.3.0 lets members open a pod in VS Code.

Changes
- `godfather vscode [pod-id]` sets up the VS Code Remote - SSH extension for a pod. It saves a 12-hour certificate for that pod, writes a `godfather-<pod-id>` entry to your SSH config, and opens VS Code on your workspace if the `code` command is installed. Run it again to renew the certificate. The menu has the same step as Set up VS Code.
- Pod image 2.3.0: a command that an SSH client sends (VS Code, `scp`, `sftp`) runs as your pod account in your workspace. Before, a member login always opened an interactive shell and ignored the command.
- Members can open local port forwards (`ssh -L`), which VS Code needs. Remote forwards stay off. The image tests now check this the way Platform signs member certificates.

Upgrade steps
- Members run `pip install -U godfather-cli`, then `godfather vscode`.
- Officers recreate each pod on `ghcr.io/theaisocietyasu/godfather-base:2.3.0`. On a 2.2.0 pod, VS Code cannot install its server.
- Services that a member starts on `127.0.0.1` on a shared pod are reachable by the other members of that pod, as they were before from a shell. Bind them to a Unix socket in your workspace, or protect them with a password or token.
