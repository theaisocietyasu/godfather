Godfather gives ASU students free compute on machines the AI Society at ASU pays for. This is a security and handover release. Upgrading needs a few manual steps; see "Upgrading from 1.0.x to 1.1.0" in DEPLOYMENT.md.

Security
- API requests are authenticated with signed tokens issued by the portal. The backend no longer trusts a Discord user ID sent in a header, which let anyone act as an admin.
- The shared organization SSH key is no longer handed out. The CLI makes its own key and gets a 12-hour certificate valid for one pod. Members are forced into their restricted account; admins get root.
- The pod image no longer writes login scripts to predictable paths in /tmp as root.

Fixes
- CPU pods can be created.
- The web file manager works with paramiko 4 and later.
- The backend image includes ssh-keygen.
- Backend CI runs lint and tests; CLI CI runs tests.

Upgrade steps
- Add GODFATHER_TOKEN_SECRET to .env. ADMIN_ROLE_ID is now required.
- Publish the new godfather-base image, then recreate existing pods.
- Members run `pip install -U godfather-cli` (1.1.0) and log in again from /cli-auth.

Docs
- README explains how access works and which file to edit for common changes. DEPLOYMENT.md covers deploys, upgrades, releases and CI secrets.
